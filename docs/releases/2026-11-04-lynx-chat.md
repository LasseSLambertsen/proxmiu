# Lynx chat and OpenRouter

The lynx opens a conversational assistant in the app when a provider key is configured. It reuses the encrypted OpenAI, Anthropic or OpenRouter settings, including the selected model. Without a key, the existing pet remains available. The presentation website explains the app behavior and retains its decorative companion.

OpenRouter supports both chat and the existing setup review through its fixed OpenAI-compatible HTTPS endpoint. Its default model is openai/gpt-4o-mini and remains editable. Switching providers requires an explicit new key; settings reads never return keys. No private hostname/referrer metadata or tools are attached.

Chat sends only intentionally typed conversation. It does not automatically attach inventory, configuration, notes or logs and cannot run infrastructure actions. The existing numeric setup review keeps its separate preview/consent workflow. Chat uses bounded alternating messages, shared AI concurrency/cooldowns, fixed provider endpoints, timeouts, bounded replies and safe redacted errors. Replies are bounded to 4000 characters with an explicit shortening marker so follow-up messages remain valid. Setup-review output retains its existing limit.

Conversation and drafts stay in app memory, clear on provider/model change, key removal or agent switch, and can be cleared manually. Failed sends retain the draft and previous successful turns. A request-generation guard prevents old responses from returning after a clear or configuration reset. Messages render as plain text. The dialog supports keyboard sending, multiline/IME input, focus restoration, conversation limits and 390px layouts.

Verification: 79 server/domain/integration tests pass; both TypeScript projects and production build pass. Browser tests cover all three providers, saving and switching to OpenRouter in Settings, inventory disclosure, configured chat/no-key pet, followups, plaintext, failure/retry, pending duplicate prevention, limits, keyboard/IME, focus, clear/reset and late replies, plus phone layout. Existing mascot and advanced-workspace regressions pass. Website companion and desktop/mobile presentation checks pass. Fresh independent reviews found no material issues in chat or the OpenRouter extension.

Provider responses were tested with controlled fixtures; no paid/live provider call was made. Publication uses CI-gated app/site PRs and preserves existing hosting/access. Existing LAN agents must update before the new endpoint is available.
