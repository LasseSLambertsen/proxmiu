# Community Scripts OS selection

The reported guest runs Debian12, while its downloaded iSponsorBlockTV executable requires GLIBC_2.39. Public Community Scripts metadata and the host-side script currently specify Debian13. Proxmiu appended Debian12/Ubuntu24.04 fallback choices to imported metadata and searched all cached choices before checking the preferred downloadable OS. This could silently choose Debian12 even while the form previewed downloadable Debian13.

Imports now retain only the declared default, or no automatic OS when metadata is missing. Read-time normalization exposes known legacy imports with only their first declared choice, while the old guessed pair `debian-12,ubuntu-24.04` becomes unknown instead of masquerading as a requirement. Saved records are not overwritten. Resolution searches cached/downloadable images per preference, rather than trying every cached fallback first. Required download failures stop creation. Ordinary templates retain intentional fallback lists, including cached allowed fallbacks when the catalogue cannot be read. Explicit OS overrides stay explicit. The Create preview/help follows the same Community policy; its manual picker remains limited to Debian/Ubuntu, and missing defaults prompt a metadata refresh rather than promise other OS choices.

Existing Debian12 guests are not upgraded or deleted. For this app, create a fresh guest using Debian13 from current metadata, preserve any needed application data and migrate deliberately. Replacing system glibc alone is not part of this fix. Saved templates with outdated first-choice metadata need an explicit refresh/re-import.

The exact legacy guessed pair is ambiguous if a user manually chose the same list; that shape is conservatively treated as unknown too. An explicit image choice or catalogue refresh resolves it.
