# Lynx chatbot implementation plan

**Goal:** Make the existing lynx open a real conversational assistant whenever an AI provider key is configured. Continue the user's existing app/site implementation and publication authorization.

**Architecture:** React chat dialog using the current authenticated agent and encrypted OpenAI/Anthropic/OpenRouter settings. The existing shared mascot script emits a cancelable wake event so the app can replace decorative wake behavior when configured; website and unconfigured app retain the companion. No new dependencies or privileges.

## Contracts and constraints

- POST `/api/ai/chat` strict body `{messages:{role:'user'|'assistant',content:string}[]}` -> `{reply:string}`.1..20 messages, each trimmed nonempty <=4000 characters, entire message content <=20000 characters, alternating user/assistant starting and ending user. Reject system/tool roles and extra fields.
- Server uses store.aiCredentials() and existing provider/model. Fixed HTTPS provider endpoints, no tools or infrastructure mutations. Existing bounded response reader/timeout/redacted errors/token redaction reused for review and chat. Max output1600tokens; chat replies capped4000characters including an explicit shortening marker, review output remains16000characters. Auth/origin hooks unchanged. One AI request at a time across review/chat,10second review cooldown and short chat cooldown2seconds. No history persisted or logged.
- System prompt identifies Lynx as Proxmiu's friendly Proxmox assistant, knows current app surfaces/features and safe advice limits; it has no automatic inventory/config/notes/log access and cannot claim changes or live observations. Only intentionally typed conversation is sent. Existing explicit numeric inventory review remains available in Settings.
- Shared `proxmiu:lynx-wake` CustomEvent is cancelable with trigger detail. Chat listener intercepts when configured, dispatches `proxmiu:lynx-dismiss` to remove any decorative panel. Both visible companion controls and existing logo Easter egg continue working. No change to landing-page auth or provider storage.
- Chat transcript and draft stay in component memory, reset on provider/model change or key removal and agent switch/unmount. Masked key never returned. Show provider/model and a concise notice that messages go to that provider and no setup data is attached automatically. Render plain text only; clear chat action, loading/error/retry handling, bounded conversation and send/keyboard controls. Enter sends, Shift+Enter newline, IME respected. Mobile390px, keyboard focus and reduced motion preserved.
