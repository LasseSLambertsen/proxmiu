# Reviewed existing NIC link state

Continue stage 1 of the approved full-administration roadmap with one bounded hardware control: edit link_down on an existing ordinary NIC of a guest observed stopped. This does not complete NIC or host networking administration. Existing TypeScript/Fastify/React and warm-glass primitives; fixtures now, designated live PVE8/9 validation later.

The coordinator selects link state only. Bridge/VLAN editing requires handling configured/pending/permission-hidden SDN identities, staged host network changes and native IPAM effects. Filtered VNet absence is not proof of absence. Raw property editors risk identity or unrelated-option loss. Keep broader edits for later networking work.

## Native contract

- Support net0–net31 for both QEMU/LXC. Common QEMU models virtio/e1000/e1000e/rtl8139/vmxnet3 need explicit MAC+bridge; LXC veth needs explicit name/MAC/bridge. Unknown/duplicate/ambiguous properties, missing identity, trunks, host-managed LXC and low-level custom container configuration stay read-only.
- Read fresh cluster resources, config?current=1, runtime status, pending, snapshots, online node, exact-node effective Sys.Audit and bounded complete active-task inventory. Require stopped resource/status, SHA1 digest, ha.managed=0 and no lock/template/pending/snapshots/active or unknown tasks. Both numeric permission values0/1 grant at the queried node; validate recent finished task rows and UPID timestamps.
- Native property strings have no invented escaping/quoting. Keep raw original tokens on the agent, replacing/appending only link_down=0/1. Preserve MAC spelling/case EXACTLY in outgoing strings: native stopped-update IPAM branches compare bridge+MAC as case-sensitive strings. Neither changes here. No direct bridge/SDN/IPAM/DHCP/power/delete/SSH operations or other config fields.
- Semantic postconditions normalize QEMU alias/explicit-model representations, MAC case, native case-insensitive booleans, numeric spellings and LXC absent type=veth. LXC custom raw directives are config.lxc pairs (including legacy lxc.network.*), not just flattened keys. Unknown options stay unsupported. No raw config, addressing, notes or credentials enter public views/provider input.

## Review, submission and recovery

GET nic-links returns {name,ready,reason?,errors,interfaces}. Each interface has nic,mac,bridge,tag,model,ifname,linkDown,canEdit,reason?; unsupported identities may be null. Inspection is on demand. POST nic-link-review accepts strict {nic,linkDown:boolean}, rejects no-op, and returns fixed identity/currentLinkDown/target linkDown/name/node/type/VMID/reviewId/expiry. Bind raw selected config, digest, guest and revision; five-minute single-use review, typed native guest name, per-guest admission reservation before awaiting checks. Reject stale/replaced evidence and changed/disappeared revision immediately before PUT. Confirmed preflight409 sends no PUT and retains draft.

Send exactly one synchronous PUT /nodes/node/type/vmid/config with netN and fresh digest. BOTH QEMU and LXC PUT return null. Do not use QEMU async POST or invent a task ID. HTTP error/timeout can follow partial write; non-null success is also unconfirmed. After null reread current config/pending/status/readiness; verify target and all original identity/unrelated option semantics. Native locking/digest remains final authority; external start/network changes are not atomically excluded by preflight. No retry/rollback/cleanup. Verified plans may return cached past result with observedAt; consumed unknown plans cannot replay, including after restart.

Verified result: {verified:true,name,node,type,vmid,interface,observedAt}. Otherwise502 inspection-required unknown outcome. No native task history/log is promised for synchronous PUT. After closing/restart inspect current interface/pending state; review IDs do not survive into replay. Refresh observed data deliberately, retain last successful reading after failures, and never unlock a consumed write merely because of a new read. Invalidate related config after any possibly submitted request independently of observation success. Agent changes close the dialog; late callbacks cannot fill new-agent caches.

## UI and verification

On-demand Network link state card uses configured connected/disconnected-on-next-start wording, not live reachability. Dialog fixes NIC/MAC/bridge/VLAN/model/name identity; only connection state is editable. Review old/new state and connectivity impact, require exact native name, expiry and fresh readiness. Server review must match original selection before storing it; replacement between open/Review or refresh requires closing and reselecting. Stale409 retains draft and requires refresh/new review; unknown removes write controls and offers read-only observation. Use existing scrollable390px dialog/footer and both themes. Long63-character valid guest names must wrap in description and confirmation label. Preserve the pinned isolated demo and mascot.
