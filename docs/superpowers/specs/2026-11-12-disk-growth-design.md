# Reviewed disk growth

Next hardware increment: grow one existing ordinary storage-backed disk on a guest observed stopped during preflight. Preserve all other disk options, CPU/network/boot settings and native notes. Use native resize rather than rewriting sanitized configuration. This does not complete full VM/LXC hardware administration. ## Native contract and scope

Both QEMU and LXC use `PUT /nodes/{node}/{type}/{vmid}/resize`, with exactly `disk`, absolute `size` in integer GiB (`16G`), and the fresh configuration SHA1 `digest`. Both supported PVE8/9 return a `resize` UPID with the selected VMID, including launch-era QEMU8.0.2+. Null/malformed responses mean acceptance unknown. Never send skiplock, relative +sizes, start/stop, config rewrites, detach/delete or guest commands.

First scope: QEMU ordinary ide/sata/scsi/virtio storage-backed raw/qcow2 disks and LXC rootfs/mp storage-backed raw/subvol volumes on explicitly supported dir/lvm/lvmthin/zfspool backends. Exclude ISO/CD-ROM, cloud-init, EFI/TPM, unused disks, passthrough, bind/device mounts, readonly/shared flags, linked-parent volumes, duplicate volume attachments, unknown ownership/size/format, unlimited quotas and unsupported backends. Snapshot exclusion is a conservative product limit, not a claim that all Proxmox snapshot resizing is unsupported.

Read fresh `config?current=1`, `/pending`, `/status/current`, snapshot inventory, online-node/storage state, canonical content listing and exact volume attributes. Authority for capacity is `GET /nodes/{node}/storage/{storage}/content/{encoded volid}`, not config size hints, maxdisk or guest usage. Require exact VMID ownership, positive safe integer bytes and consistent format. Block running/paused/unknown guests, templates, locks, unreadable/pending changes, HA-managed guests and active/unconfirmed native guest tasks. Native status must explicitly report ha.managed0; missing HA data is not proof of unmanaged state. Count special/unused volume references when rejecting aliases, while keeping those devices unselectable. Complete task visibility requires the current principal’s effective Sys.Audit at the exact node, queried through /access/permissions with only path (no userid). Both native propagation flags0 and1 grant a listed privilege; missing/invalid flags are unverified. source=active can contain recent finished tasks: exempt only valid matching identities with start/endtime and a consistent terminal result, and keep malformed/running/unknown rows blocked. Storage availability is advisory and not a reservation or allocation guarantee; show it and any shortfall during review.

## Review and execution

A bounded five-minute single-use review names guest/node/type/ID, disk/volume/storage, current capacity, absolute target, allocation delta, observed storage availability and filesystem implications. Target is integer GiB1–65536 and strictly greater than authoritative current bytes; safe integer multiplication is mandatory. Require typed guest-name (or displayed ID fallback) confirmation. Bind source identity, saved connection revision, SHA1 digest, exact raw property value, canonical volume ownership/format/current bytes and selected target; do not return raw configuration to the browser.

Claim a per-guest execution reservation synchronously before awaiting checks, preventing simultaneous submissions from separate reviews. Reinspect source/state/digest/volume/storage/native resize activity before the PUT; reread current connection revision immediately before submission. Native config locking/digest provides final configuration conflict protection. The stopped rule is an app preflight policy: resize has no native stopped-only parameter, and another client may start a guest between checking and worker execution. Do not claim atomic stopped-only enforcement or stop guests automatically.

Accepted tasks belong to the existing guest/node and use existing bounded native status/log/history routes. New growth reviews check active resize tasks as well as fresh capacity. Every plan is consumed before PUT; no automatic retry, shrink, rollback or cleanup after errors/unknown acceptance. An uncertain result directs manual inspection of Activity/native tasks and actual capacity before any new explicit review. Absolute targets bound a redundant attempt to the reviewed size rather than adding an increment. Leaving/restarting uses native retained task history; do not fabricate a task ID or declare failure solely from a lost response.

QEMU volume growth does not expand guest partitions/filesystems. LXC may run filesystem checks and expansion; failures can be warnings after block/config growth. Show success/warning/failure/unknown separately and reread requested versus observed capacity after completion. Allocation can round to KiB/MiB/LVM extents; never promise exact bytes or filesystem capacity.

## Integration and validation

Use focused `server/src/guest-disk-growth.ts` for inventory/reviews/execution, existing authenticated guest-scoped routes and task access, typed web API/query hooks and a disk-capacity card/dialog. Preserve unknown native property options by never serializing the disk configuration. Inspect storage deliberately on demand, because ownership and capacity require multiple bounded native reads. After a terminal result invalidate insights/resource settings/notes digest/overview/operations and native task status independently of successful capacity observation. Refresh disk inventory with the new observed read; retained native history remains explicitly refreshable through its existing controls. No new broad PVE privilege: existing VM.Config.Disk, Datastore.AllocateSpace/Audit and LXC's additional VM.Config.Options cover this scope.

Tests: exact QEMU/LXC PUT and UPID; positive authoritative capacity/format/ownership; absolute target and safe integer conversion; stale digest/property/current bytes/connection; pending deletes and unknown reads; unsupported disk/flags/backends/parents/duplicates; snapshots/locks/HA/active resize; shrink/equal/expiry; two concurrent reviews; rounding and filesystem warnings; null/lost result and no replay; source option/note/NIC preservation and zero power/config/delete/SSH calls. Add actual local TLS-client/agent fixtures plus browser review/typed confirmation/stale draft/task recovery/unknown acceptance/390px themes. Run standard typecheck/full tests/build/demo and fresh independent review before publishing.
