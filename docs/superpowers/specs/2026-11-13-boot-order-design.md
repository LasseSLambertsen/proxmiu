# Reviewed VM boot-device order

Continue the approved stage-1 hardware roadmap with reordering an existing explicit enabled-device set on a stopped QEMU VM. This does not complete boot or hardware administration. Keep native notes, encrypted optional AI and consent boundaries, the warm-glass UI and390px usability. Fixtures now; actual SeaBIOS/OVMF/media/PXE/startup validation remains a designated live gate.

## Scope and choice

The coordinator chooses membership-preserving reordering. Enabling/disabling devices or converting legacy/default mode changes boot eligibility; setting a nonempty order also automatically deletes native bootdisk and normalizes away legacy. Those wider edits need their own explicit review. A raw boot-string editor would hide these effects. This first slice requires only order=... with at least two distinct supported existing devices, bootdisk absent, no legacy/other subkeys and no custom args. Visible legacy smp/cdrom/snapstate and unused-volume aliases that native writers would remove also stay read-only. No empty order, membership/firmware/device/power change, attach/detach/delete/resize, SSH or guest commands.

Supported enabled targets: ordinary storage-backed IDE0–3/SATA0–5/SCSI0–30/VirtIO0–15 data disks, configured ordinary storage ISO CD-ROM references, and ordinary configured net0–31 NICs recognized by the existing pure NIC parser. Empty/host CD-ROM, cloud-init, host storage/passthrough/scsiblock, USB/PCI, EFI/TPM/unused/unknown/absent target keys remain unsupported. EFI/TPM and other configured devices remain untouched. A single unsupported enabled entry makes the whole order read-only; never drop entries. Existing read-only disk or disconnected NIC state may be shown with a warning and is preserved. No claim that configured media has a bootloader, ISO boots, PXE works or the OS will start.

## Native reads and preservation

Read exact guest identity from cluster resources, config?current=1, runtime status, pending, snapshots, online node, exact-node effective Sys.Audit and bounded complete active-task inventory. Require stopped in both resource/runtime, valid SHA1 digest, absent lock/template, managed=0 HA, no pending/snapshots/unconfirmed tasks. Unknown template flags stay read-only; numeric Sys.Audit0/1 both grant on the exact path. Existing VM.Config.Disk governs boot, not VM.Config.Options; no role elevation. Configured bridge/device/firmware data is read, never rewritten.

Parse only a canonical nonempty order=dev;dev property; reject duplicate keys/devices, whitespace/control/quoted/escaped/unusual separators and unknown/legacy subkeys. Preserve all configured device raw strings and unrelated configuration values. The small pure NIC property reader may be exported from guest-nic-link for common classification; its write behavior must remain unchanged. Classify configured disk/ISO references without lossy GuestInsights rewriting; availability and bootability are not inferred from a filename and no datastore read is required merely to reorder existing keys. Unknown unrelated raw device options can be preserved because no device property is submitted; ambiguous critical identity/media/passthrough fields remain unsupported.

Inventory shape: {name,ready,reason?,errors,sourceIdentity,order:BootDevice[],excluded:{id,reason}[]}. BootDevice={id,kind:'disk'|'cdrom'|'network'|'unsupported',label,identity,warning?}. Identity is an opaque SHA256 of raw boot-relevant data, not a native config digest or raw properties. Include current boot and full configured device/firmware/autostart-relevant evidence; exclude notes/addressing text from public views. Other config stays server-side. This verifies observable API values, not unseen physical file comments, masked secret bytes or special sections. Reject visible native cleanup hazards before submission; unexpected post-write differences remain unconfirmed. Unsupported inventories may have sourceIdentity:null. Excluded devices are informative and never selectable in this slice.

## Review and execution

GET boot-order is on demand and QEMU-only. POST boot-order-review takes strict {sourceIdentity,order:string[]}; target must be a different permutation of exactly the same enabled set. Verify sourceIdentity against fresh evidence, then return {reviewId,name,node,type:'qemu',vmid,sourceIdentity,currentOrder:BootDevice[],proposedOrder:BootDevice[],expiresAt}. Bind guest/node/type/VMID, name, native digest, raw boot/device evidence and connection revision to a five-minute single-use review. Require exact native guest-name confirmation for POST boot-order {reviewId,confirm}. The frontend also checks server review source/current/proposed identities against the fixed opening selection and draft; a replacement requires close/reselect.

Consume and reserve per guest synchronously before awaiting admission. Recheck all evidence and revision immediately before exactly one PUT /nodes/node/qemu/vmid/config with only boot:'order='+permutation.join(';') and fresh digest. Require bootdisk still absent. Both PVE8/9 PUT return synchronous null; do not use POST or invent an UPID/log. Config locking/digest is native final authority, and another administrator can still start the VM after preflight. Confirmed preflight409 sends no PUT and retains draft; transport/error/non-null or partial apply is unconfirmed, never retry/rollback/power/cleanup automatically.

After null read current config/pending/runtime/readiness again. Verify exact requested order, unchanged membership, absent bootdisk, identical raw devices/firmware and all unrelated returned current-config values except digest/boot, plus stopped/no pending. Use recursively sorted canonical comparison so native JSON object ordering is irrelevant. Result is {verified:true,name,node,type:'qemu',vmid,sourceIdentity,order:BootDevice[],observedAt}. Verified reviews can return their cached historical result; unknown consumed reviews cannot replay, including after restart. Handle disappeared revision before PUT as no-write conflict and after PUT as unconfirmed.

## UI and recovery

Add a QEMU-only on-demand Boot device order card and shared dialog. Source identity/devices remain fixed; arrow buttons reorder existing rows with keyboard focus and a polite position update. Never infer or add a device from default boot helpers. Review exact old/new enabled order and labels, warn that next start may enter another OS/installer or fail, require typed name and expiry. Keep the VM stopped; saving does not start it or prove boot success. Long names/volume labels wrap, the390px body scrolls, footer stays reachable and themes stay unchanged.

Known stale409 retains the draft and requires fresh inspection/new review. Unknown writes remove write controls but permit deliberate current-order reads with last-good retention; observation never unlocks a consumed request. No native task/log is promised. After closing/restart inspect current order and pending state. Invalidate related config after any possibly submitted request independently of observed-read success. Agent switch closes and late old-agent responses cannot populate a new cache. Do not change public demo, mascot or global styles.
