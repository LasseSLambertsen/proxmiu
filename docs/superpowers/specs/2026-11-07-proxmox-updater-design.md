# Proxmox host updater

## Intent and chosen scope

The user asked for a Proxmox updater helper and explicitly chose **review and install from Proxmiu**. A node Updates dialog will perform an explicit update check, present the exact package plan, require typing the node name, and report the real durable result. Normal updates stay within the installed Proxmox major release; no repository editing, major upgrades, package removals, downgrades, forced repair, automatic guest migration or reboot. Existing node reboot/shutdown controls remain separate.

Approaches considered: native Proxmox APT APIs require broad Sys.Modify even for update listing and offer no equivalent bounded reviewed installation endpoint; unrestricted root SSH would expand the existing trust boundary; a dedicated opt-in forced-command helper provides the required operations without changing the normal Proxmox role. The latter is the controller's design choice under standing delegated implementation/publication instructions. No actual host setup or upgrade is performed by development tools.

## Host boundary and installation

- New Python3.11+ stdlib helper at `/usr/local/lib/proxmiu/host-updater`, root-owned0755, root state `/var/lib/proxmiu-host-updater`0700 and files0600. A root-run public installer adds a dedicated key with `restrict,command="/usr/bin/python3 -I /usr/local/lib/proxmiu/host-updater --rpc --node <installed-node>"`. Node is installer-generated and strictly validated; mismatch on another node fails before any RPC. The forced command ignores SSH_ORIGINAL_COMMAND and accepts only bounded JSON on stdin. No general shell, PTY, forwarding, user-controlled executable/argv/path/environment or sudo permission is granted. RPC, worker and APT guard have separate fixed argv entry points; only RPC is reachable with the SSH key.
- Enrollment checks effective sshd/root-key policy before granting access: only safe locale AcceptEnv names, PermitUserEnvironment=no, no external AuthorizedKeysCommand/ForceCommand, ed25519 host key enabled. Reject active unassessable Match/Include policy rather than altering sshd; loader/shell-startup/Python environment cannot be accepted before the forced command starts. Python runs with absolute interpreter and -I; subprocess environment/PATH is fixed. Existing keys remain intact; setup is explicit/idempotent, helper updates/removal are administrator actions.
- Support Proxmox's root-owned `/root/.ssh/authorized_keys` symlink to `/etc/pve/priv/authorized_keys` without replacing/chmodding the symlink or assuming bare POSIX append/rename/flock on pmxcfs. Serialize our enrollments with PVE::Cluster::cfs_lock_domain('proxmiu-updater-enroll',...), compare/reread/verify the existing file and use Proxmox's own `PVE::Tools::file_set_contents` atomic writer, as its SSH setup does. Preserve entries/permissions; fail on conflicting duplicates, changed input, unsupported/no-quorum writes. For a local root-owned regular authorized_keys use a local installer lock. Binding the forced command to the node is mandatory because cluster authorization can be shared. Other root administrators remain trusted; detect concurrent input changes rather than overwrite them.
- Each connection/node gets a separate updater ed25519 keypair, distinct from the guest/app SSH key. Private material is AES-encrypted in the agent store and never returned. Regenerating the ordinary app SSH key must not affect updater access. Do not install anything automatically from the Proxmox one-command installer or grant Sys.Modify/Sys.Console.
- Host package mechanics live in a separate root-owned fixed module `/usr/local/lib/proxmiu/host-updater-apt.py`, loaded by the isolated main helper from that exact protected path. Installer downloads main helper, APT module and guard wrapper from the same immutable project commit. This is an implementation split, not another RPC surface or configurable import path.
- Administrator setup downloads the helper/installer from the configured trusted public project source using fail-checked downloads, never executes a file from an unprivileged agent-owned checkout as host root. Do not use `curl | bash`. Provide a concrete copyable setup command containing only the public key; root installer returns node identity and the host ed25519 SHA256 SSH fingerprint. No host SSH configuration changes to permit root login, no password login enablement. Explain unsupported SSH settings instead.
- Dedicated agent transport validates the pinned SHA256 host fingerprint (raw host key), uses only that node's key, and rejects mismatches before any request. Do not reuse `ssh.connect` because it currently accepts all host keys for disposable guests. Configure fixed host/port/pin explicitly per saved connection/node, and verify helper protocol+returned node before enabling. No silent TOFU, automatic retarget or fallback to root credentials. Fresh Proxmox inventory must identify the selected online node before operations.

## Protocol v1

One JSON object followed by EOF per SSH exec channel. Client requests have exact keys; unknown keys/verbs are rejected. RPC stdin64KiB maximum, request deadline10s. Agent session setup15s; whole RPC30s; output256KiB maximum, validate JSON/runtime fields and safe errors. Never return raw transport errors, private keys, bodies or arbitrary upstream output. No secrets/host logs automatically reach AI or provisioning history.

Requests:
- `{"action":"inspect"}`: protocol, node, installed Proxmox version/major, Debian codename, helper readiness and current/latest job. Pure read, no package refresh.
- `{"action":"check"}`: admit one durable root job, refresh APT metadata with any repository failure fatal, validate supported same-major repositories/healthy dpkg, and simulate updates. Return accepted job ID immediately.
- `{"action":"status","jobId":"<32 lowercase hex>"}`: bounded saved job/status/log/plan. Unknown IDs safely fail; state remains recoverable after agent/SSH disconnect.
- `{"action":"apply","planId":"<32 lowercase hex>","digest":"<64 lowercase hex>"}`: consume the host-issued, unexpired reviewed plan once and admit a durable install job. No client package names, command lines, URLs or options accepted.

Responses are JSON `{protocol:1,node,result:<info-or-job>}`; failures `{protocol:1,node,error:{code,message}}` with fixed code/message, not raw exceptions. Inspect info `{proxmoxVersion,proxmoxMajor,codename,machineIdHash,ready,reason?,latestJobId?,rebootSuggested}`; reason is a fixed code/message. Other verbs return Job `{id,state,phase,startedAt,finishedAt?,log:string[],logTruncated?,plan?,rebootSuggested?,error?}`. States `running`, `review`, `success`, `failed`, `interrupted`; phases `check` or `apply`. Check completion with a nonempty install plan is `review`; no upgrades is `success`. Plan `{id,digest,expiresAt,proxmoxMajor,codename,packages:[{name,architecture,installed,candidate}],kernelChange}`; installed is null for a newly installed dependency. Agent validates safe Debian package names/architectures/version strings, exact identities and bounded lengths before exposing/applying. Max2000 packages and96KiB serialized complete plan; reject `plan_too_large`, never authorize a truncated list. Budget actual encoded JSON plus logs under256KiB.

## Reviewed APT operation

- Root helper supports Proxmox8/Bookworm and9/Trixie. Inspect installed `pve-manager` and `proxmox-ve` versions, `/etc/os-release`, node identity; missing/mixed/unsupported installations fail closed. Active apt source suite tokens must be the host codename, its security/updates/backports variants, or the explicit third-party `nodistro` suite. Floating `stable`, another Debian suite, malformed/unparseable source definitions and insecure/trusted=yes sources block automation. Parse both .list and deb822 .sources with disabled entries honored; do not emit credential-bearing repository URLs. Existing root-managed signed repositories remain the trust authority.
- Check uses fixed environment/PATH/LC_ALL=C, no client-supplied env. Read `dpkg --audit` and refuse unhealthy state; never run automatic repair. Use `apt-get update` with error-on-any and a fixed same-major simulation equivalent to `apt-get -s dist-upgrade`. Any removals, downgrades, held-package changes, package-parser ambiguity or candidate Proxmox major changes block the plan. Standard new dependencies may be reviewed as explicit additions.
- Plan expires after600s, with boot identity and monotonic age authoritative and ISO expiresAt for display. Host stores canonical plan and a digest of content+normalized inventories for dpkg status/selections/holds/pending state, sources, preferences, Signed-By keyrings/global trust, APT lists and effective APT configuration. Exclude locks/download temporaries/logs; reject unsupported root/state/dpkg-executable overrides. Store opaque IDs/root records atomically; caller cannot supply plan contents. Recheck in admission, worker and locked guard; changed state becomes stale, never silently refreshed/installed. Architecture:all remains distinct from native architecture in simulation, targets and archives.
- Apply exact reviewed `package:architecture=version` targets, with no removals, no unauthenticated/insecure installs, no downgrade/held-package override, and no reboot. Preserve existing config defaults (`--force-confdef`/`--force-confold`) and report that packages may restart host services. Never issue a generic unattended full-upgrade whose changed solver result could install unreviewed packages.
- Close the simulate/apply race using APT VERSION3 action feed (Bookworm2.6.1/Trixie3.0.3 supported). Generate a root-only per-job late `apt-get -c <fixed generated path>` overlay: `#clear DPkg::Pre-Install-Pkgs;`, guard first, then every original hook in original order with original protocol/InfoFD options preserved. A dedicated fixed guard executable `/usr/local/lib/proxmiu/host-updater-apt-guard` execs absolute Python -I main helper --guard with only validated job ID. Set that executable's DPkg::Tools::Options Version3 and InfoFD0; require VERSION3 header. Validate final effective config including Binary::apt-get overrides. Reject nonempty DPkg::Pre-Invoke (it runs earlier), unsupported/unreproducible hook configurations or dangerous overrides; do not silently drop hooks. Never rely on -o list append to prepend our guard.
- In the guard, after APT owns its locks, revalidate digest/dpkg health. Parse the entire v3 action set, reject removal/downgrade/unreviewed configuration/duplicate/missing/extra/malformed actions; require exact reviewed install identities. Inspect each actual regular protected-cache .deb with fixed dpkg-deb argv and match name/version/architecture against stream and plan; reject unexpected paths/symlinks. No unreviewed package/config script can run first. Retain --no-remove and explicitly disable insecure/downgrade/held-change allowances. Trusted administrators and existing root-managed hooks are not sandboxed. Tests exercise review-state drift and actual-solver/action/archive drift.

## Lifecycle and diagnostics

- Fixed root systemd-run worker survives SSH/browser/agent disconnect. Under helper lock persist active job, consumed-plan marker, boot ID and deterministic unit before launch; worker reacquires that lock and validates admission. Another admission is rejected during handoff. Start failure is saved failed; consumed plan never replays. Global host flock spans work. One operation globally per agent, with reservation persisted across restart and unresolved contact loss; no cluster batch. Block forgetting/deleting an unresolved active target until terminal state can be verified. External APT/dpkg locks are respected, never killed/deleted/bypassed.
- Inspect/status remain responsive while work holds its operation lock, using atomic records and nonblocking reconciliation; never wait behind APT to display progress. Guard must not deadlock on the parent's operation lock. Serialize short record writes separately or use equivalent safe ownership; admission handoff must not be mistaken for a lost unit before its launch is reconciled.
- On lost unit, boot change or reconnect, reconcile saved state and actual unit identity/activity; missing evidence means interrupted, never success. Never infer success from disconnect/replay/repair. Success requires exit zero, every reviewed version installed/configured and healthy dpkg; partial/ambiguous outcomes remain failed/interrupted. SSH/RPC timeout closes transport only, not the unit/APT.
- Retain at most20 completed jobs; never evict active work. Public/persisted diagnostics use bounded fixed phase/package events, not arbitrary maintainer-script output whose secrets cannot be guaranteed redacted. Max500 lines/128KiB total, each2048 chars; truncate explicitly within actual256KiB response budget and96KiB plan cap. Detailed raw diagnostics stay outside app-managed storage/output and are not automatically collected. Root records atomic/root-only, no symlink/traversal; failed persistence/admission never starts work. Reboot suggestion from marker/kernel changes is advisory, never an automatic reboot or proof that absent marker means none needed.

## Agent and UI

Routes under `/api/clusters/:id/nodes/:node/updater`: GET info, POST `/setup` generates pending key/public setup data, PUT `/configuration` verifies endpoint/pin/helper-node before durable enablement, DELETE `/configuration` forgets local access with manual revocation guidance, POST `/check`, POST `/apply` only `{planId,digest,confirmNode}`, GET `/jobs/:jobId`. Global GET `/api/host-updaters` lists public configured targets and cached latest job metadata, never private keys. Fresh online node validation precedes new setup/config/check/apply writes; known job inspect/status remain readable via pinned SSH during Proxmox API outages caused by updates. Auth/origin/DNS/schema guards always apply. Persist plan ID/digest binding to cluster/node/config+key revisions on review; apply must match that binding and typed confirmation. Configuration changes invalidate reviews; reject changes/connection deletion/forget while admitted work remains unresolved. Completed removal erases local keys/config without touching host keys. No private keys, raw host logs or package data in AI/browser storage.

Node menu **Updates…** opens a dedicated `/nodes/:clusterId/:node/updates` page, also linked from a Settings configured-target list so status remains reachable when Proxmox inventory is unavailable. Protected setup/confirmation may use existing dialogs. Show opt-in key/setup command/pin, readiness, Check updates, live bounded events, complete package review/versions/additions, expiry/stale handling, typed node confirmation, **Install reviewed updates**, durable result and manual recovery/reboot suggestion. No auto repo fix/repair/upgrade/reboot. Reset review on agent/target/config change, no mutation retries. Leaving accepted work explains it continues; never label that Cancel. Preserve warm glass/Geist/focus/errors/390px; one batched desktop/mobile/light/dark visual pass plus at most one material-fix confirmation. Pinned public demo remains non-operational/unchanged.

## Verification and rollout limits

All development tests use synthetic Proxmox/SSH/systemd/APT/dpkg fixtures and temporary directories. Never run apt update/install, root-key installation, guest/host commands, migrations or reboots on real systems from tools. Python helper/installer tests inject dependencies through imported functions; production CLI has no test path/env bypass. Test command execution, not source-text snapshots. Linux helper tests and ShellCheck/syntax/compile are required; Node API/transport fixtures work on CI Ubuntu+Windows, with explicit platform limits for Unix-only helper tests. Meaningful RED→GREEN for helper policies and agent/browser flow, full project tests/typechecks/normal+demo builds, independent security/quality reviews and exact-head CI gate publication. Real-host enrollment/update remains an honest user-run validation step after source release.
