# Native guest console

Continue the delegated roadmap with Proxmox termproxy access from a guest workspace, useful before guest networking/SSH works. Controller-selected scope is LXC consoles and existing QEMU serial sockets. Keep SSH as a separate choice. Host shell, graphical VNC/SPICE, automatic serial/getty configuration and guest power actions are outside this iteration.

## Architecture and protocol

Reuse the existing xterm terminal and JSON browser transport shape. A separate `/api/console` WebSocket route authorizes the agent token in its first bounded connect frame, preserving existing upgrade origin/DNS-rebinding checks. No token in URLs and no unauthenticated upstream action. Browser frame contains only connect identity `{clusterId,node,guestType,vmid,cols,rows,token?}`; reject unknown fields and client-selected URLs, ports, tickets, users, commands or serial devices. Only one connect attempt per socket; malformed/binary/oversized frames fail closed. First frame deadline5s and setup deadline15s. No automatic reconnect.

Before every connect, resolve the current stored connection and fresh `/cluster/resources?type=vm`: exact guest type/VMID/node, running, not a template. Reject moved/missing/stopped/offline targets without silently choosing another node or starting a guest. For QEMU, read fresh config and choose the first `serial0`..`serial3` whose value is exactly `socket`. No socket means an actionable unsupported-configuration error before termproxy POST. Never alter guest hardware or OS.

POST `/nodes/{node}/{lxc|qemu}/{vmid}/termproxy` (QEMU includes server-chosen serial). Validate returned user (no protocol delimiters/control characters), ticket, port5900..5999, and bounded fields. Open WSS on the same saved Proxmox host/port and fixed guest `vncwebsocket` path, using current token or password-cookie authentication and that record's TLS verification setting. Query carries the short-lived native ticket only upstream; return/persist/log none of it. Use `binary` WebSocket subprotocol. Do not expose raw upstream errors, URLs, headers, ticket, API credentials or upstream authentication exchange to the browser or logs.

Wire reference is upstream `proxmox/pve-xtermjs/xterm.js/src/main.js`: send `user:ticket\n`, require `OK` before connected/input, preserve trailing output and handle the acknowledgement split across frames. Input is `0:<UTF-8 byte length>:<text>`, resize `1:<cols>:<rows>:`, keepalive `2` every30s. Decode output without corrupting multibyte characters split across frames (stream decoder or binary-safe browser support). Browser JSON frames≤256KiB, console input≤64KiB UTF-8 per frame; safely chunk larger paste in the console client. Reject invalid sizes (cols2..500,rows2..300). Upstream payload and queued-buffer ceilings1MiB; no unbounded pre-connect queues. Latest resize may be retained while connecting; input cannot reach upstream before OK. In-flight close/error/timeout must close both ends, clear timers and prevent a late connect. Remote termproxy workers may time out naturally after cancelled setup; do not issue broad task-kill commands.

## Product and permissions

Guest workspace shows separate SSH terminal and Console choices; console needs running/available guest, not an IP address. Opening its dialog does not open a session. Show exact guest/node and describe native Proxmox access, possible guest login and QEMU serial requirement. User presses Connect; reconnect is explicit, dismiss/Disconnect closes transport, errors remain visible and actionable. Close a stale dialog on target/agent/migration/offline changes rather than reconnecting automatically. Preserve existing SSH controls, clipboard/key toolbar and lifecycle.

Add only `VM.Console` to the installer role definition for new/re-run setup and document an explicit manual role update for existing installations. Never grant rights through a console request. Do not add `Sys.Console`. Promote already installed `ws`8.22.0 to an explicit runtime dependency if imported directly; no new transport library/version tree is needed. New output/session credentials are transient and never enter history, AI context or localStorage.
