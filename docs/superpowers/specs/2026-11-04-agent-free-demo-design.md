# Agent-free product demo

Continue the delegated roadmap with an interactive sample environment visitors can explore without installing or connecting an agent. Controller-selected approach: a curated read-only tour built from the app's actual tokens and pure components, with an independent HTML/module entry. This preserves real session/auth/write behavior and has a smaller safety boundary than mocking all real API endpoints. A screenshot carousel would not exercise discovery/filtering/history; a fully simulated operational agent would duplicate too much behavior and obscure which actions are real.

## Product and visual contract

Extend the established Operate surface: Geist fonts, warm glass, floating dark rail, amber/teal, quieter paper light mode and continuous background. Match existing density and 248px desktop/72px tablet navigation; a four-item floating dock on phones. Do not redesign the real app or website. Persistent, visible `Demo · Sample data` notice, a clear route back to the website and `Install Proxmiu` at `/#install`. Copy is precise with restrained, perceptive Lynx character.

Use fixed, plainly synthetic data and documentation addresses (192.0.2.x/.invalid). Never claim live health or real provisioning. Screens: Overview with sample nodes/guest usage and navigation; searchable/status/type-filtered Guests with clear empty/reset behavior and clickable names; guest workspace with allocation/notes and the real pure ResourceHistory chart (metric switching and keyboard inspection); Templates with sample configuration details and no Create button; Activity with success/error/interrupted history, selectable saved steps and plaintext logs. All state is in memory except a separate `proxmiu-demo-theme` preference; reload resets exploration. Hash routing provides shareable/reloadable guest/history links without SPA hosting rewrites. Unknown routes have an explicit recovery path.

## Isolation/build contract

Separate `web/demo.html` + `web/src/demo/*` entry, `npm run build:demo` writes `dist/demo/index.html` with asset base `/demo/`. Vite's normal app entry/output is unchanged. The demo imports no app session/agent/API/query/write/SSH/provider implementation. Reuse pure UI primitives, chart and formatting helpers only. No agent URL/token/password fields, connection probing, provider calls, WebSockets, infrastructure actions, simulated successful writes or normal app localStorage access. CSP `connect-src 'none'`, no form submission and no external scripts/fonts; no PWA manifest/service worker.

The existing website serves the artifact at `/demo/` on its current Netlify project/domain. A Node build script stages a fixed allowlist of marketing assets into `dist/`, builds the demo from a pinned full app commit and copies only `dist/demo` into staged `/demo`. Pin a merged app commit in `demo-source.json`, fixed public repository, immutable SHA; verify fetched HEAD. Optional local source argument must match that exact commit and be clean. No floating branch, credential input, new dependency/hosting project, runtime API or private build source in the publish directory. Include a public `demo/build.json` source SHA for provenance. Keep domain/access/global security headers and mascot asset unchanged. Build failure leaves the currently published site intact through normal Git CD.

## Verification

Meaningful browser checks on built `/demo/`: preseed real-looking sentinel agent/keys/views and assert no normal-key access/change, zero API/fetch/WS/provider calls, loaded local assets, navigation/filter/empty/reset/guest/chart/template/history/unknown/deep-link reload behavior, separate theme persistence, keyboard focus and desktop/tablet/390px light/dark bounds. Local static delivery is allowed; no real infrastructure/provider. Capture desktop/mobile in one batched visual pass and allow at most one confirmation after material fixes. App typecheck/full tests/build and demo build must pass on Linux/Windows Node22; add demo compilation to existing CI.

Site build tests pin/source validation, allowed public files, no source/dependency/secret publication, failure-before-replace and provenance. Existing presentation/mascot tests and `/demo/` smoke checks pass on local staged output, exact-head Netlify preview and production. Publish app first, then pin its actual merged SHA in site, review/verify final site and publish through the authorized subagent.
